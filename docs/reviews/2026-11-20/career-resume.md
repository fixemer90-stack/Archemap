# Career: повторный вход без новой генерации

Статус: исправлено, опубликовано, exact-SHA CI и production-проверка завершены.

## Подтверждённая причина

Страница `/products/career` при повторном выборе профиля загружала только анкету. Состояние генерации и ключ её создания хранились в React state/ref и терялись после перезагрузки. Повторная отправка завершённой анкеты создавала новый ключ, а сервер защищал только повтор одного ключа, не повторное создание для того же Career-профиля.

Чтение конкретного сохранённого отчёта и кнопка «Обновить» в reader используют GET и не создают новую генерацию. Ошибка относится к возвращению через продуктовый вход и повторной отправке.

- [x] Повторный вход и reload открывают сохранённый готовый/деградированный отчёт либо возобновляют наблюдение за активной генерацией.
- [x] Ошибка загрузки или терминальная неудача не подменяются новой платной попыткой.

- [x] Сервер переиспользует существующую генерацию при новом ключе обычного create, включая конкурентные запросы; явная regenerate остаётся отдельной операцией.
- [x] Проверки чужого профиля/ключа и ограничения доступа сохранены.
- [x] Независимый code/security review закрыт, локальные проверки и exact-SHA CI завершены.

- [x] Native повторный вход/reload и новые create-ключи не добавляют Career generation/segment rows и не вызывают новый LLM-прогон.

## Проверка безопасного rollout

Уже существующая Career-генерация `partial_failure` является терминальным результатом, а maintenance probe ошибочно относил её к незавершённой работе. Добавлен узкий тест и исправлен только этот терминальный статус; активная генерация и неизвестный исход по-прежнему не считаются завершёнными.

RED: `tests/unit/test_career/test_career_maintenance_terminal.py` — 1 failed по ожидаемому отрицанию settled для `partial_failure`.

GREEN: этот тест вместе с `test_staging_maintenance_probe.py` и `test_staging_maintenance_transport.py` — 19 passed. Изменённые probe/test прошли Ruff lint/format и mypy.

Независимый review чернового операционного контроллера потребовал усилить привязку archive/manifest/tree/image, запрет перезаписи приватных runtime-путей, готовность scheduler перед открытием ingress и финальную проверку runtime перед маркерами. Все четыре замечания устранены отдельным fix-проходом и закрыты независимым re-review точного SHA-256 `5c383b8d30b82ce32e756b50522086534d87467e8e7e099a41db786c3d05911d`; родитель повторно проверил хеш и AST.
