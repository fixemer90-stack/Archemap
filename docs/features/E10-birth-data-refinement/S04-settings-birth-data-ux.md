# S04: UX данных рождения в Settings

## Статус

⬜ Не начато

## Контекст

Сейчас `/settings` содержит имя, email и смену пароля. Пользователь не видит полные исходные данные расчёта и не может безопасно инициировать их уточнение.

## Что сделать

Добавить отдельную карточку «Данные рождения» после карточки профиля.

### Состояние просмотра

Показывать:

- выбранный профиль; при нескольких профилях — явный selector;
- время рождения или «Время не указано»;
- понятную точность: «Точное», «Примерное», «Неизвестно»;
- место рождения;
- спокойное пояснение: «Изменение времени или места повлияет на натальную карту и отчёт»;
- кнопку «Уточнить данные»;
- серверное `next_available_at`, если действует ограничение.

### Состояние редактирования

- Поле времени `HH:MM`.
- Выбор точности `exact / approximate / unknown` с человеческими подписями.
- Поиск места с debounce и выбором конкретной подсказки.
- Координаты/timezone скрыты от ручного редактирования.
- Кнопка сохранения активна только при валидной выбранной подсказке и материальном изменении.
- Перед отправкой — подтверждение: будет создан новый расчёт, текущий отчёт останется доступен до готовности.

### Состояние cooldown

Кнопка выключена, но данные доступны для просмотра. Текст строится по серверному timestamp, например:

```text
Следующее уточнение будет доступно 14 сентября в 13:00.
```

Не использовать только локальный 24-часовой таймер как источник истины. После фокуса окна/возврата на страницу статус перечитывается с backend.

### Состояние пересчёта

После `202`:

- показать «Данные сохранены — обновляем расчёт»;
- отслеживать revision/generation status;
- сохранить доступ к текущему отчёту;
- при `deterministic_ready` предложить открыть обновлённый отчёт;
- при `failed` не обещать потерянный результат и не предлагать оплатить снова.

### Ошибки

- `429`: обновить UI по `next_available_at`, не показывать общий сбой.
- `birth_data_unchanged`: объяснить, что данные не отличаются.
- Геокодер недоступен: не разрешать сохранить произвольные координаты/default timezone.
- Session expired: стандартный auth-refresh/login flow.

## Микрокопирайтинг

Не использовать технические слова `input_hash`, `generation_id`, `LLM`, `v2`, `timezone`. Разрешены понятные формулировки: «исходные данные», «натальная карта», «обновляем расчёт», «текущий отчёт остаётся доступен».

## Критерии приёмки

- [ ] Карточка корректно показывает время, точность и место выбранного профиля.
- [ ] При нескольких профилях пользователь явно выбирает изменяемый профиль.
- [ ] Нельзя изменить дату рождения в этом интерфейсе.
- [ ] Нельзя сохранить место без выбора подсказки.
- [ ] Exact/approximate/unknown корректно управляют обязательностью времени.
- [ ] UI показывает backend-derived cooldown и обновляет его после 429/refocus.
- [ ] Успех запускает понятное состояние пересчёта без скрытия старого отчёта.
- [ ] Ошибка фоновой генерации не предлагает повторную оплату.
- [ ] Mobile layout, keyboard navigation, labels и focus states проверены.
- [ ] Имя и смена пароля продолжают работать независимо от cooldown.
