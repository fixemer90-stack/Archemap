# Child: проверка после восстановления инфраструктуры

Статус: **ожидает восстановления, не выполнено**.

Владелец сообщил об утрате сервера после кибератаки. Он согласовал закрытие #51 после публикации исправления и зелёного CI, без ожидания production rollout. Это не доказательство проверки или безопасности восстановленной инфраструктуры. Настоящий документ — отдельный незавершённый пункт запуска; не расширяет разрешения на инфраструктурные изменения или платные provider calls.

Исправление и локальное evidence: [BUG-51](../reviews/2026-11-13/BUG-51-child-thematic-evidence.md). Продуктовые и эксплуатационные границы: [E22 follow-ups](../features/E22-child-report/PRODUCT-FOLLOW-UPS.md).

## До запуска

- [ ] Отдельно согласованы целевая инфраструктура, release SHA и безопасный план запуска.
- [ ] Проверены provenance и целостность восстановленных данных/артефактов; неизвестная сохранность старого сервера не трактуется как PASS.
- [ ] Подтверждены актуальные конфигурация и секреты без публикации значений.
- [ ] Отдельно согласованы synthetic fixture, generation operation/idempotency key и provider budget. Mock-only проверка не выдаётся за real-provider acceptance.
- [ ] Восстановлена и проверена health/readiness backend, worker, scheduler и frontend; зафиксированы реально выполняемые revisions.

## Проверка Child нового контракта

- [ ] Новая полная генерация использует Guidance Facts V4 / narrative V5; старые артефакты не переписываются.
- [ ] Умеренные/смешанные показатели сохраняют своё объяснение в natural_contact, friction_zones, conflict_cycle и not_personal; проверены тема, показатель, наблюдение и source refs, не только ready status.
- [ ] Отсутствующее наблюдение, неоднозначность и отсутствие выраженного перекоса различаются; конкретный конфликтный цикл и намерения не выдуманы.
- [ ] После commit и новой сессии API возвращает сохранённые bodies, корректные contract/prompt pins и неизменённую историческую версию.
- [ ] Desktop/mobile показывают точные сохранённые bodies и ограничения без overflow, технических reason codes или автоматической повторной генерации.
- [ ] Нативный PDF сохраняет текст, порядок разделов и пояснения неопределённости; извлечённый текст сопоставлен с API/reader.
- [ ] Исторические read/retry/PDF версии сохраняют hashes; отдельно проверены ownership и lineage отказы.
- [ ] Результаты и ограничения записаны с точным release SHA, режимом provider и фактическим числом attempts.

## Deployment boundary

Push кода не запускает deploy jobs: `build-push-deploy.yml` допускает staging/production rollout только через явный `workflow_dispatch` и существующий registry gate. Сейчас manual dispatch не выполняется. Снятие этой границы и новый rollout требуют отдельного согласования.
