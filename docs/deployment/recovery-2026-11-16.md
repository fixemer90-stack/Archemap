## Required operational overlay

All operational commands must include the recovery overlay, not just the default production Compose file:

```sh
cd /opt/astrotype
docker compose -p astrotype --env-file .env.production \
  -f docker-compose.prod.yml -f recovery.compose.json ps
```

- `recovery.compose.json` binds the verified image identities to backend, workers and frontend, and mounts `deploy/Caddyfile.recovery`.
- The recovery Caddy configuration serves production apex/www only. `staging.astrotype.ru` still resolved to the old VPS during preflight; staging was not restored and its DNS was not changed.
- Recovery ingress explicitly returns JSON `503` for registration/email-recovery/Yandex OAuth and new checkout while the corresponding credentials remain unconfirmed. Payment webhooks are not blanket-blocked by the new-checkout matcher; the application has no PSP credentials or restored payment objects.
- Removing the overlay without reviewing these gates changes public behavior. Restore integration credentials privately, verify the relevant provider/callback contracts, and adjust only the corresponding ingress gate deliberately.
