# Astrotype v2 Balance Calculation: Elements and Modalities

## Цель

Документ фиксирует deterministic-методику расчёта баланса стихий и модальностей для Astrotype v2.

Баланс не генерируется LLM и не берётся из текста отчёта. Он считается из сохранённых точек натальной карты и должен быть воспроизводимым для web, Android, PDF и будущих клиентов.

Главное правило:

```text
один и тот же набор точек карты и один и тот же набор весов используется
и для баланса стихий, и для баланса модальностей
```

То есть нельзя считать стихии по одной формуле, а модальности по другой.

---

## Что считается балансом

### Баланс стихий

Показывает распределение веса карты по четырём стихиям:

```text
Огонь
Земля
Воздух
Вода
```

Каждая точка карты попадает в стихию через знак, в котором она находится.

### Баланс модальностей

Показывает распределение того же веса карты по трём модальностям:

```text
Кардинальная
Фиксированная
Мутабельная
```

Каждая точка карты попадает в модальность через тот же знак.

## Включённые точки карты

Важно: численные веса ниже — не универсальная астрологическая догма и не “канон”. Это стабильная продуктовая эвристика Astrotype v2 для визуального баланса в личностном отчёте.

Асцендент и MC включены как углы карты, а не как планеты. Асцендент получает высокий вес, потому что сильно описывает первый контакт с миром и внешний стиль реакции. MC получает умеренный вес: он важен для верхней оси карты и публичной траектории, но в личностном отчёте не должен автоматически доминировать над личными планетами.

Для v2 MVP баланс считается по этим точкам:

| Точка     | Вес | Почему включена                                                        |
| --------- | --: | ---------------------------------------------------------------------- |
| Солнце    | 2.0 | центральная витальность, самоидентификация                             |
| Луна      | 2.0 | эмоциональная регуляция, базовая реакция                               |
| Асцендент | 1.6 | первый контакт с миром, внешний стиль реакции                          |
| Меркурий  | 1.2 | мышление, речь, обработка информации                                   |
| Венера    | 1.2 | ценности, симпатии, контакт, эстетика                                  |
| Марс      | 1.2 | действие, напор, границы, желание                                      |
| MC        | 1.0 | публичная траектория, верх карты; умеренный вес для personality report |
| Юпитер    | 0.8 | расширение, вера, горизонт смысла                                      |
| Сатурн    | 0.8 | структура, ограничение, зрелость                                       |
| Уран      | 0.5 | индивидуализация, разрыв шаблона                                       |
| Нептун    | 0.5 | идеализация, тонкая чувствительность                                   |
| Плутон    | 0.5 | глубина, кризис, трансформация                                         |

Важно: эти веса применяются одинаково к стихиям и модальностям.

## Статус весов

В астрологии нет единой общепринятой количественной таблицы, которая бы доказывала, что Асцендент, MC, Венера, Меркурий и другие точки должны иметь именно такие численные веса. Традиционно Асцендент считается одним из ключевых факторов карты наряду с Солнцем и Луной; MC также важен как угол карты, но его роль сильнее связана с публичной траекторией, статусом и направлением реализации.

Поэтому `weighted_chart_points_v1_personality_heuristic` — это не утверждение “такова база астрологии”, а зафиксированная методика продукта. Её задача — дать стабильный, объяснимый и воспроизводимый UI-баланс для личностного отчёта. Если позже появится отдельный карьерный отчёт, он может иметь другую версию метода, где MC получает больший вес.

## Алгоритм

Для каждой включённой точки карты:

```text
1. Взять знак точки.
2. Найти стихию знака.
3. Найти модальность знака.
4. Добавить вес точки в bucket стихии.
5. Добавить тот же вес точки в bucket модальности.
```

После суммирования:

```text
percentage = category_score / total_score * 100
```

Где:

```text
total_score = сумма весов всех включённых точек
```

Округление для UI:

```text
1. Посчитать raw percentages.
2. Округлить методом largest remainder так, чтобы сумма была ровно 100%.
3. Raw values сохранять для debug/analytics, rounded values отдавать в UI.
```

## Псевдокод

```python
POINT_WEIGHTS = {
    "Sun": 2.0,
    "Moon": 2.0,
    "Ascendant": 1.6,
    "Mercury": 1.2,
    "Venus": 1.2,
    "Mars": 1.2,
    "MC": 1.0,
    "Jupiter": 0.8,
    "Saturn": 0.8,
    "Uranus": 0.5,
    "Neptune": 0.5,
    "Pluto": 0.5,
}

element_scores = {"Огонь": 0, "Земля": 0, "Воздух": 0, "Вода": 0}
modality_scores = {"Кардинальная": 0, "Фиксированная": 0, "Мутабельная": 0}

for point in included_chart_points:
    weight = POINT_WEIGHTS[point.name]
    sign = point.sign

    element = SIGN_TO_ELEMENT[sign]
    modality = SIGN_TO_MODALITY[sign]

    element_scores[element] += weight
    modality_scores[modality] += weight

# Same denominator because the same points and weights are used.
total = sum(POINT_WEIGHTS[p.name] for p in included_chart_points)

element_percentages = normalize_to_percentages(element_scores, total)
modality_percentages = normalize_to_percentages(modality_scores, total)
```

## UI правила

1. Не показывать баланс как абсолютную “силу” человека.
2. Подписывать, что это относительное распределение веса карты.
3. Не использовать разные методики для стихий и модальностей.
4. Если отображаются проценты, они должны суммироваться до 100% внутри своего блока.
5. В расширенном/debug виде можно показывать метод и включённые точки.
6. В основном отчёте достаточно показывать распределение и доминирующий акцент.

## Out of scope для MVP

Не включать в balance v1:

- астероиды;
- Лунные узлы;
- Part of Fortune;
- Vertex;
- управителей домов как дополнительные точки;
- аспекты как усилители баланса;
- dignity/debility multipliers;
- house emphasis multipliers.

Эти расширения можно добавить позже отдельной версией метода, например:

```text
weighted_chart_points_v2
```

Но текущая версия должна оставаться стабильной и воспроизводимой.
